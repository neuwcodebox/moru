# SPEC.md

# 로컬 대화형 이미지 생성기 — 요구사항 정의서

## 1. 목적

로컬 이미지 생성 모델과 로컬 LLM을 이용해, 사용자가 이미지 생성 프롬프트를 직접 알 필요 없이 자연어 대화만으로 이미지를 생성·수정할 수 있는 데스크톱 앱을 만든다.

앱의 핵심 UX는 일반 대화형 AI와 유사하되, AI의 응답은 텍스트가 아니라 이미지다.

사용자는 다음과 같이 사용한다.

1. 자연어로 원하는 이미지를 입력한다.
2. 앱이 내부적으로 이미지 생성 프롬프트를 작성한다.
3. 즉시 이미지를 생성해 대화창에 표시한다.
4. 이어서 “밤으로 바꿔줘”, “표정만 무표정하게”처럼 수정 요청을 입력한다.
5. 이전 이미지의 실제 프롬프트를 기준으로 새 프롬프트를 만들고 새 이미지를 생성한다.
6. 과거 이미지에서 Fork하여 다른 방향으로 이어갈 수 있다.

---

## 2. 핵심 원칙

- UI는 하나의 대화창 중심으로 구성한다.
- 사용자는 기본적으로 실제 이미지 생성 프롬프트를 직접 다루지 않는다.
- 사용자 요청을 전송하면 항상 프롬프트 생성/수정 후 즉시 이미지를 생성한다.
- 실제 프롬프트는 이미지별 상세 팝업에서만 확인·수정할 수 있다.
- 모든 수정은 기존 결과를 파괴하지 않고 새 가지를 만드는 Fork 방식으로 처리한다.
- 자연어 수정과 수동 프롬프트 수정은 동일한 Fork 개념으로 취급한다.
- 이미지와 프롬프트, 생성 설정, 분기 관계를 모두 로컬에 영구 저장한다.
- 외부 API 없이 로컬 추론을 기본으로 한다.

---

## 3. 메인 화면

화면은 하나의 대화 영역과 하단 입력 영역으로 구성한다.

대화에는 기본적으로 다음만 노출한다.

- 사용자 자연어 요청
- 생성된 이미지 결과

AI가 내부적으로 만든 실제 생성 프롬프트는 기본 대화 흐름에 노출하지 않는다.

### 3.1 입력 영역

화면 하단에 하나의 자연어 입력창을 둔다.

입력창 용도:

- 첫 이미지 생성 요청
- 현재 이미지의 수정 요청
- Fork 기준 이미지의 수정 요청

기본 동작:

- Enter: 전송
- Shift+Enter: 줄바꿈
- 전송 후 즉시 프롬프트 생성/수정
- 이어서 즉시 이미지 생성

### 3.2 새 작업

`새 작업` 버튼은 입력창 우측 상단 가까이에 배치한다.

새 작업 실행 시:

- 빈 작업을 시작한다.
- 현재 분기 기준 이미지를 제거한다.
- 새 작업의 첫 요청은 새 프롬프트 생성으로 처리한다.
- 기존 작업 기록은 삭제하지 않는다.

### 3.3 생성 설정

입력창 좌측에 생성 설정 아이콘을 둔다.

설정 팝업에서 다음을 변경할 수 있다.

- 모델
- 이미지 크기
- Steps
- CFG
- Seed

설정값은 이후 생성에 사용된다.

---

## 4. 기본 생성 흐름

### 4.1 첫 요청

현재 작업에 기준 이미지가 없을 때 사용자가 요청을 전송하면 새 이미지 생성으로 처리한다.

처리 순서:

1. 사용자 자연어 요청 저장
2. 로컬 LLM에 새 이미지 프롬프트 생성 요청
3. LLM이 실제 이미지 생성 프롬프트 반환
4. 현재 생성 설정과 프롬프트로 이미지 생성
5. 이미지 결과를 대화창에 추가
6. 생성된 이미지가 현재 가지의 최신 기준 이미지가 됨

### 4.2 이어지는 수정 요청

현재 가지에 기준 이미지가 있을 때 사용자가 요청을 전송하면 수정 요청으로 처리한다.

처리 순서:

1. 기준 이미지의 실제 생성 프롬프트 조회
2. 사용자 자연어 수정 요청 저장
3. 로컬 LLM에 기존 프롬프트 + 수정 요청 전달
4. LLM이 수정된 전체 이미지 생성 프롬프트 반환
5. 새 이미지 생성
6. 새 결과를 현재 가지 끝에 추가
7. 새 결과가 새로운 기준 이미지가 됨

LLM은 부분 패치가 아니라 항상 완성된 전체 프롬프트를 반환한다.

---

## 5. 이미지 결과

각 생성 이미지는 대화창 안에 표시한다.

### 5.1 기본 동작

- 이미지 클릭: 전체 화면 이미지 뷰어
- 이미지 하단:
  - 프롬프트
  - Fork
  - 분기가 있을 경우 branch selector

불필요한 설명, 모델명, 해상도, seed 등의 메타데이터는 기본 화면에 노출하지 않는다.

### 5.2 프롬프트

`프롬프트` 버튼을 누르면 팝업을 연다.

팝업에는 다음을 표시한다.

- 실제 생성 프롬프트
- 모델
- Width / Height
- Steps
- CFG
- Seed

실제 생성 프롬프트는 편집 가능하다.

기능:

- 닫기
- 복사
- 이 프롬프트로 생성

프롬프트를 직접 수정해 생성하면 원본을 덮어쓰지 않고 해당 이미지에서 새 Fork를 만든다.

---

## 6. Fork

Fork는 과거 이미지에서 새로운 수정 흐름을 만드는 기능이다.

### 6.1 자연어 Fork

이미지의 `Fork` 버튼을 누르면 해당 이미지가 임시 기준 이미지가 된다.

입력창 가까이에 작은 Fork 상태를 표시한다.

예:

```text
Fork: #12 ×
```

이후 자연어 요청을 보내면:

1. 해당 이미지의 실제 프롬프트를 기준으로 사용
2. 자연어 수정 요청을 LLM에 전달
3. 새 전체 프롬프트 생성
4. 이미지 생성
5. 해당 이미지에서 새로운 가지 생성
6. 새 가지를 현재 활성 가지로 전환

`×`를 누르면 Fork 대기 상태를 취소한다.

### 6.2 수동 프롬프트 Fork

이미지의 실제 프롬프트를 직접 수정한 뒤 생성한 경우도 동일한 Fork로 처리한다.

차이:

- 자연어 Fork: LLM이 프롬프트 수정
- 수동 Fork: 사용자가 직접 프롬프트 수정

### 6.3 기존 흐름 보존

Fork는 기존 이미지와 기존 가지를 덮어쓰지 않는다.

모든 생성 결과는 불변 기록으로 유지한다.

---

## 7. 분기 탐색

전체 트리를 별도 그래프로 표시하지 않는다.

현재 선택된 경로만 일반 대화처럼 보여준다.

분기점에 여러 child가 있으면 작은 branch selector를 표시한다.

```text
‹ 1 / 3 ›
```

이를 이용해 sibling branch를 전환할 수 있다.

---

## 8. 이미지 전체 화면 보기

이미지를 클릭하면 전체 화면 뷰어를 연다.

지원 기능:

- 원본 비율 유지
- 화면 맞춤
- 확대/축소
- 드래그 이동
- Esc로 닫기

---

## 9. 생성 설정

### 9.1 지원 항목

- 모델
  - Anima Turbo
  - Anima Aesthetic
- Width
- Height
- Steps
- CFG
- Seed

### 9.2 Seed

- 기본값: Auto
- Auto이면 생성 직전에 실제 seed 결정
- 생성 결과에는 실제 seed 저장
- 숫자 직접 입력 가능

### 9.3 해상도

프리셋과 직접 입력을 지원한다.

권장 프리셋:

- 1024 × 1024
- 832 × 1216
- 1216 × 832
- 768 × 1344
- 1344 × 768

---

## 10. 작업과 이력

하나의 `작업`은 하나의 대화 트리다.

각 사용자 요청은 다음 정보를 가진다.

- ID
- 자연어 요청
- 생성 시각
- 기준 이미지 ID
- 요청 유형

각 이미지 결과는 다음 정보를 가진다.

- ID
- 이미지 경로
- 생성 시각
- 실제 생성 프롬프트
- 생성 설정
- 부모 이미지 ID
- 원인이 된 사용자 요청 ID
- 생성 방식

앱 재시작 후에도 작업과 분기를 완전히 복구해야 한다.

---

## 11. 로딩 및 오류

사용자 요청 이후 아래 상태를 간단한 progress UI로 표시한다.

- 프롬프트 준비
- 이미지 모델 준비
- 이미지 생성

가능하면 이미지 생성 step progress를 표시한다.

실패 시:

- 기존 작업 이력을 손상시키지 않는다.
- 간단한 오류 메시지를 표시한다.
- 동일 요청을 재시도할 수 있다.

---

## 12. 저장

성공한 생성은 즉시 로컬에 저장한다.

저장 대상:

- 이미지 파일
- 실제 생성 프롬프트
- 사용자 요청
- 생성 설정
- 부모/자식 관계
- 작업 ID
- 생성 시각

---

## 13. 모델 관리

앱 실행 시 필요한 모델 파일 존재 여부를 검사한다.

지원:

- 기존 로컬 모델 경로 지정
- 앱 내부에서 모델 다운로드

사용자는 내부 모델 형식이나 추론 백엔드를 이해할 필요가 없어야 한다.

---

## 14. 비기능 요구사항

- Windows 11 우선 지원
- 오프라인 사용 가능
- 외부 API 키 불필요
- 사용자 이미지/프롬프트 외부 전송 금지
- 이미지 생성 중 UI 정지 금지
- 앱 종료 시 내부 추론 프로세스 정상 종료
- 생성 이력 손상 방지
- Windows portable ZIP 형태로 배포한다.
- 별도 설치 프로그램을 요구하지 않는다.
- 사용자는 ZIP을 압축 해제한 뒤 단일 실행 파일을 더블클릭하여 앱을 실행할 수 있어야 한다.
- Python, Node.js, ComfyUI 등 내부 런타임을 사용자가 별도로 설치하거나 실행하지 않아야 한다.
- 콘솔 창, 로컬 서버 주소, 내부 백엔드 UI 등을 사용자에게 노출하지 않는다.

## 16. 완료 기준

다음이 모두 동작하면 MVP 완료로 본다.

1. 새 작업에서 자연어 요청을 보내면 새 이미지가 생성된다.
2. 두 번째 요청부터 직전 이미지 프롬프트를 기준으로 자연어 수정이 적용된다.
3. 사용자 요청과 생성 이미지가 하나의 대화 흐름으로 표시된다.
4. 이미지를 클릭하면 전체 화면으로 볼 수 있다.
5. 이미지별 실제 프롬프트를 팝업에서 확인할 수 있다.
6. 실제 프롬프트를 직접 수정해 새 Fork 이미지를 생성할 수 있다.
7. 이미지의 Fork 버튼으로 과거 이미지에서 자연어 수정 branch를 만들 수 있다.
8. 기존 branch는 보존된다.
9. 분기점에서 sibling branch를 탐색할 수 있다.
10. 모델, 해상도, Steps, CFG, Seed를 설정할 수 있다.
11. 모든 이미지·프롬프트·설정·분기 관계가 로컬에 저장된다.
12. 앱 재시작 후 기존 작업과 현재 branch를 복구할 수 있다.
13. Windows에서 별도 런타임 설치 없이 portable ZIP을 풀고 실행 파일만으로 실행할 수 있다.
