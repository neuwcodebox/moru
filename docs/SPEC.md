# SPEC.md

# 로컬 대화형 이미지 생성기 — 요구사항 정의서

## 1. 목적

로컬 이미지 생성 모델과 로컬 LLM을 이용해, 사용자가 이미지 생성 프롬프트를 직접 알 필요 없이 자연어 대화만으로 이미지를 생성·수정할 수 있는 데스크톱 앱을 만든다.

앱의 핵심 UX는 일반 대화형 AI와 유사하되, AI의 응답은 텍스트가 아니라 이미지다.

사용자는 다음과 같이 사용한다.

1. 자연어로 원하는 이미지를 입력한다.
2. 앱이 내부적으로 이미지 생성 프롬프트를 작성한다.
3. 즉시 이미지를 생성해 대화창에 표시한다.
4. 이어서 “밤으로 바꿔줘”, “표정만 무표정하게”처럼 수정 요청을 입력한다.
5. 이전 이미지의 실제 프롬프트를 기준으로 새 프롬프트를 만들고 새 이미지를 생성한다.
6. 과거 이미지에서 Fork하여 다른 방향으로 이어갈 수 있다.

---

## 2. 핵심 원칙

- UI는 하나의 대화창 중심으로 구성한다.
- 사용자는 기본적으로 실제 이미지 생성 프롬프트를 직접 다루지 않는다.
- 사용자 요청을 전송하면 항상 프롬프트 생성/수정 후 즉시 이미지를 생성한다.
- 완료된 이미지의 실제 프롬프트는 이미지별 상세 팝업에서 확인·수정할 수 있다.
- 모든 생성 결과는 불변 기록으로 보존한다.
- 자연어 요청은 새 대화 행을 만들고, 다시 생성과 수동 프롬프트 수정 생성은 원래 행의 이미지 버전으로 묶는다.
- 분기는 선택한 이미지까지의 대화를 새 작업으로 복사한다.
- 이미지와 프롬프트, 생성 설정, 분기 관계를 모두 로컬에 영구 저장한다.
- 외부 API 없이 로컬 추론을 기본으로 한다.

## 3. 메인 화면

화면은 하나의 대화 영역과 하단 입력 영역으로 구성한다.

대화에는 기본적으로 다음만 노출한다.

- 사용자 자연어 요청
- 생성된 이미지 결과

완료된 이미지의 실제 생성 프롬프트는 상세 팝업과 이미지 hover에서 확인한다.
생성 중에는 이미지가 나타날 자리에 placeholder를 표시하고 작성 중인 프롬프트를
실시간으로 보여준다. Thinking 중에는 `생각 중…` 상태만 표시하고 사고 내용은 노출하지 않는다.
프롬프트 텍스트는 placeholder의 이미지 영역 안에 통합하며 별도 하단 패널을 만들지 않는다.
대화가 길어지면 대화 영역만 스크롤하고 헤더와 하단 입력 영역은 창 안에 유지한다.
페이지 전체에 별도의 스크롤바가 생기지 않는다.
생성 placeholder와 이미지 로딩 placeholder는 요청에 저장된 이미지 크기와 비율로
공간을 확보한다. 창 너비와 대화 이미지의 표시 상한에 맞춰 축소하며, 프롬프트 길이로
이미지 영역의 크기를 늘리지 않는다. 생성 중 및 hover의 프롬프트는 세로 중앙에
배치하고, 길어지면 이미지 영역 안에서 세로 스크롤한다.

### 3.1 입력 영역

화면 하단에 하나의 자연어 입력창을 둔다.

입력창 용도:

- 첫 이미지 생성 요청
- 현재 이미지의 수정 요청
- Fork 기준 이미지의 수정 요청

기본 동작:

- Enter: 전송
- Shift+Enter: 줄바꿈
- 전송 후 즉시 프롬프트 생성/수정
- 이어서 즉시 이미지 생성
- 전송 버튼은 작업 접수 후 중지 버튼으로 바뀌며, 중지·완료·실패 후 전송 버튼으로 돌아온다.
- 취소 버튼을 진행 표시 영역에 따로 두지 않는다.
- 대화가 맨 아래가 아니면 입력창 중앙 상단에 맨 아래로 이동하는 플로팅 버튼을 표시한다.
- 사용자가 이전 대화를 읽는 동안 새 텍스트나 이미지가 나타나도 스크롤 위치를 강제로 바꾸지 않는다.

### 3.2 새 작업

`새 작업` 버튼은 입력창 우측 상단 가까이에 배치한다.

새 작업 실행 시:

- 빈 작업을 시작한다.
- 현재 분기 기준 이미지를 제거한다.
- 새 작업의 첫 요청은 새 프롬프트 생성으로 처리한다.
- 기존 작업 기록은 삭제하지 않는다.

### 3.3 생성 설정

입력창 좌측에 생성 설정 아이콘을 둔다.

설정 팝업에서 다음을 변경할 수 있다.

- 모델
- 이미지 크기
- Steps
- CFG
- Seed

설정값은 이후 생성에 사용된다.

같은 팝업의 접힌 고급 영역에서 프롬프트 LLM의 컨텍스트 크기, 출력 토큰 한도,
thinking 사용 여부, 추론 수준과 최근 요청 수를 변경할 수 있다.

## 4. 기본 생성 흐름

### 4.1 첫 요청

현재 작업에 기준 이미지가 없을 때 사용자가 요청을 전송하면 새 이미지 생성으로 처리한다.

처리 순서:

1. 사용자 자연어 요청 저장
2. 로컬 LLM에 새 이미지 프롬프트 생성 요청
3. LLM이 실제 이미지 생성 프롬프트 반환
4. 현재 생성 설정과 프롬프트로 이미지 생성
5. 이미지 결과를 대화창에 추가
6. 생성된 이미지가 현재 세션의 최신 기준 이미지가 됨

### 4.2 이어지는 수정 요청

현재 세션에 기준 이미지가 있을 때 사용자가 요청을 전송하면 수정 요청으로 처리한다.

처리 순서:

1. 기준 이미지의 실제 생성 프롬프트 조회
2. 사용자 자연어 수정 요청 저장
3. 로컬 LLM에 기준 프롬프트 + 최근 요청/선택된 결과 프롬프트 + 수정 요청 전달
4. LLM이 수정된 전체 이미지 생성 프롬프트 반환
5. 새 이미지 생성
6. 새 결과를 세션의 새 대화 행에 추가
7. 새 결과가 새로운 기준 이미지가 됨

LLM은 부분 패치가 아니라 항상 완성된 영어 프롬프트를 반환한다. 기준 이미지의 프롬프트가 현재 상태이고 최근 이력은 지시 대상을 이해하는 보조 맥락이다. 새 요청은 과거 요청보다 우선한다.
시스템 지침에는 이미지 생성 모델이라는 역할만 설명하며 특정 모델 이름을 넣지 않는다. 적절한 booru 태그와 시각적 자연어 묘사를 함께 사용한다.
지침은 출력 계약, 요청 해석, 대상별 속성·행동 연결, 태그 선택, 최종 검토를
구분해 설명하고, 생성과 수정 각각에 맞는 작성 예시를 포함한다.
태그 선택표는 기본 프리셋이 아니다. 요청하지 않은 인물·외모·스타일·등급을
추가하지 않으며 여러 인물의 속성은 각 대상에 연결한다.
수정 시 변경과 충돌하는 이전 묘사를 교체하고 나머지는 유지한다.
예시는 시스템 지침에 넣으며 실제 대화 이력으로 취급하지 않는다.

## 5. 이미지 결과

각 생성 이미지는 대화창 안에 표시한다.

### 5.1 기본 동작

- 이미지 클릭: 전체 화면 이미지 뷰어
- 이미지 하단:
  - 재생성 아이콘과 `다시`
  - 연필 아이콘과 `수정`
  - 클립보드에 이미지 자체를 복사하는 `복사` 버튼
  - 브랜치 아이콘과 `분기`
  - 여러 이미지 버전이 있으면 좌우 버전 선택기

불필요한 설명, 모델명, 해상도, seed 등의 메타데이터는 기본 화면에 노출하지 않는다.
이미지에 마우스를 올리거나 이미지 버튼에 키보드 초점을 두면 반투명 blur 커버 위에
생성 프롬프트를 표시한다. 생성 중 텍스트와 같은 스타일을 사용하며 클릭 시 뷰어를 연다.
프롬프트를 불러오지 못하면 커버 안에 오류를 표시한다.
이미지 뷰어를 여는 순간 프롬프트 커버를 숨기며, 뷰어를 닫고 초점을 복원하는 것만으로
커버를 다시 띄우지 않는다. 실제 마우스 움직임이나 새 키보드 초점 탐색으로 다시 표시한다.

### 5.2 프롬프트

`수정` 버튼을 누르면 프롬프트 팝업을 연다.

팝업에는 다음을 표시한다.

- 실제 생성 프롬프트
- 모델
- Width / Height
- Steps
- CFG
- Seed

실제 생성 프롬프트는 편집 가능하다.

기능:

- 닫기
- 복사
- 이 프롬프트로 생성

복사 완료는 버튼 안의 체크 아이콘과 짧은 애니메이션으로 표시한다.
별도 성공 문구를 삽입해 레이아웃을 움직이지 않는다. 실패는 명확하게 표시한다.

프롬프트를 직접 수정해 생성하면 LLM을 거치지 않고 해당 행에 새 이미지 버전을 만든다. `다시`도 현재 보이는 이미지의 프롬프트를 그대로 사용하며 현재 생성 설정으로 생성한다. Seed Auto이면 새 seed를 결정한다. 생성 중 상태와 실패 시 재시도는 해당 행에서 표시한다.

---

## 6. 분기: 세션 복사

이미지의 `분기` 버튼을 누르면 그 이미지가 속한 대화 행까지 새 작업으로 복사하고 즉시 새 작업을 연다.

- 이전 행의 요청, 선택된 이미지와 버전 기록을 복사한다.
- 선택한 행은 현재 표시된 이미지만 복사하며 그 이후 대화는 포함하지 않는다.
- 복사된 이미지가 새 작업의 다음 자연어 수정 기준이 된다.
- 기존 세션과 이미지 기록은 보존한다. 이후 요청과 버전 선택은 두 작업에서 독립적으로 저장한다.
- 임시 분기 상태나 분기 취소 버튼을 표시하지 않는다.
- 분기 성공 후 새 작업으로 전환되었음을 짧은 알림으로 표시한다. 실패 시 성공 알림을 표시하지 않는다.

## 7. 이미지 버전 탐색

`다시`와 수동 프롬프트 수정 생성은 새 대화 행을 추가하지 않는다. 같은 행에 좌우 선택기를 표시한다.

```text
‹ 1 / 3 ›
```

선택기는 해당 행의 이미지를 바꾸며 다른 행을 숨기거나 삭제하지 않는다.
선택한 버전은 앱 재시작 후에도 복원하고, 다음 자연어 요청은 마지막으로 선택한 이미지의 실제 프롬프트를 기준으로 수정한다.
상하 방향키로 현재 대화의 이전/이후 이미지 행을 탐색하고, 좌우 방향키로 선택한 행의
이미지 버전을 탐색한다. 이미지 행의 시작/끝에서는 더 이동하지 않고 버전은 선택기와 같이 순환한다.
입력 중인 텍스트, 설정 입력, 다른 팝업과 IME 조합은 방해하지 않는다. 빈 요청 입력창에서는 탐색할 수 있다.
버전 변경은 생성/다른 작업 처리 중에는 수행하지 않는다.

## 8. 이미지 전체 화면 보기

이미지를 클릭하면 전체 화면 뷰어를 연다.

지원 기능:

- 원본 비율 유지
- 화면 맞춤
- 확대/축소
- 드래그 이동
- Esc로 닫기
- 상하 방향키로 대화의 이미지, 좌우 방향키로 이미지 버전 이동

이동한 이미지는 대화와 뷰어에 함께 반영한다. 이미지가 바뀌면 확대와 이동 위치를 초기화한다.
뷰어를 닫으면 마지막으로 탐색한 이미지에 초점을 돌려 대화의 선택을 유지한다.

맞춤·축소·확대·닫기는 하나의 작은 상단 도구 모음에 배치하고 별도 제목 행을 두지 않는다.
휠 확대·축소는 커서 아래의 이미지 지점이 화면에서 움직이지 않도록 하고,
도구 모음의 확대·축소는 현재 뷰어 영역 중앙의 이미지 지점을 유지한다.
이미지를 이동한 뒤에도 같은 기준을 적용한다. 화면 맞춤은 배율과 이동을 초기화한다.
뷰어의 휠·드래그·이미지 탐색은 뒤 대화의 스크롤 위치를 바꾸지 않는다.
설정, 모델 설정, 프롬프트 팝업을 포함해 모든 팝업이 열린 동안 배경 대화와 입력을
잠근다. 팝업 내부는 스크롤할 수 있고, 스크롤 경계에 도달해도 배경으로 이어지지 않는다.

## 9. 생성 설정

### 9.1 지원 항목

- 모델
  - Anima Turbo
  - Anima Aesthetic
- Width
- Height
- Steps
- CFG
- Seed

Turbo의 생성 기본값은 Steps 10, CFG 1.0이며 Aesthetic은 Steps 40, CFG 4.5이다.
모델을 변경하면 해당 모델의 권장 Steps와 CFG를 설정 화면에 적용한다. 이후 직접 조절할 수 있다.

### 9.2 Seed

- 기본값: Auto
- Auto이면 생성 직전에 실제 seed 결정
- 생성 결과에는 실제 seed 저장
- 숫자 직접 입력 가능

### 9.3 해상도

프리셋과 직접 입력을 지원한다.

권장 프리셋:

- 1024 × 1024
- 832 × 1216
- 1216 × 832
- 768 × 1344
- 1344 × 768

### 9.4 프롬프트 LLM 고급 설정

- 컨텍스트 크기: 기본 4096 tokens, 1024~32768 범위의 정수
- 출력 토큰 한도: 기본 2048 tokens, 1 이상이며 컨텍스트 크기보다 작은 정수
- Thinking 사용: 기본 켜짐, 설정에서 끌 수 있음
- 추론 수준: 낮음/보통(기본)/높음. 출력 한도에서 최종 프롬프트용 512토큰과
  여유 128토큰을 뺀 나머지의 50%/75%/100%를 thinking 예산으로 사용한다(소수점 버림).
  기본 출력 한도에서 낮음/보통/높음의 예산은 각각 704/1056/1408토큰이다.
  출력 한도가 640 이하이면 자유 추론 없이 최종 프롬프트 작성으로 넘어간다.
  이 예약 공간은 프롬프트 LLM의 출력 토큰 기준이며 이미지 모델의 고정 입력 한도가 아니다.
- 최근 요청 수: 기본 4개, 0~20의 정수. 0이면 이력을 전달하지 않는다.

최근 성공한 요청과 해당 행에서 선택한 이미지 프롬프트를 user/assistant 쌍으로 전달한다. 현재 기준 행까지의 맥락만 포함한다. 컨텍스트에서 출력 한도를 먼저 확보하고, 실제 채팅 템플릿의 토큰 수가 초과하면 오래된 쌍부터 제외한다. 현재 기준 프롬프트와 새 요청은 자르지 않으며 이 둘이 너무 크면 설정 변경을 안내한다.

컨텍스트는 입력과 출력을 합친 크기이며, 출력 한도에는 thinking 토큰도 포함된다.
설정은 로컬에 저장하고 재시작 후 복원한다. 변경은 다음 생성부터 적용하며,
진행 중인 작업의 설정은 변경하지 않는다. 재시도는 현재 LLM 설정을 사용한다.
지원하지 않는 모델에서 thinking 끄기를 요청하면 오류를 표시한다.
thinking을 켜면 생성 placeholder에 `생각 중…`만 표시하고, 최종 프롬프트가 나오기
시작하면 `프롬프트 작성 중…`으로 전환한다. 사고 내용은 UI에 전달하거나
완료된 이미지의 프롬프트, 영구 이력에 저장하지 않는다.
저장된 사용자 설정을 자동으로 다른 기본값으로 전환하지 않는다.
개발 단계에서는 최신 DB 스키마만 지원하며 버전별 스키마 마이그레이션을 수행하지 않는다.

## 10. 작업과 이력

하나의 `작업`은 대화 행과 각 행의 이미지 버전으로 구성된 세션이다.

각 사용자 요청은 다음 정보를 가진다.

- ID
- 자연어 요청
- 생성 시각
- 기준 이미지 ID
- 요청 유형
- 이미지 버전의 원래 대화 행 ID

각 이미지 결과는 다음 정보를 가진다.

- ID
- 이미지 경로
- 생성 시각
- 실제 생성 프롬프트
- 생성 설정
- 부모 이미지 ID
- 원인이 된 사용자 요청 ID
- 생성 방식

앱 재시작 후에도 작업과 분기를 완전히 복구해야 한다.

## 11. 로딩 및 오류

사용자 요청 이후 아래 상태를 대화 안의 이미지 placeholder에 표시한다.

- 프롬프트 작성 중… / thinking을 켜면 생각 중…
- 이미지 모델 준비
- 이미지 생성

로딩 아이콘을 함께 표시하고 이미지 생성 중에는 현재 step/전체 steps와 진행률을 갱신한다.
생성 결과가 도착하면 placeholder를 실제 이미지로 교체한다. 하단 입력 영역에는 진행 상태를 표시하지 않는다.

실패 시:

- 기존 작업 이력을 손상시키지 않는다.
- 프롬프트 작성·이미지 생성 실패 모두 요청 당시 이미지 크기와 비율의 placeholder 안에
  경고 아이콘, 간단한 오류 메시지와 재시도 버튼을 가로·세로 중앙 정렬해 표시한다.
- 경고 아이콘을 감싸는 별도 배경이나 테두리 없이 아이콘만 표시한다.
- 실패 placeholder는 붉은 톤의 배경과 테두리로 구분하며 오류를 하단 입력 영역에 중복 표시하지 않는다.
- 동일 요청을 재시도할 수 있고, 접수되면 해당 요청의 실패 표시를 진행 placeholder로 전환한다.
- 재생성·수동 프롬프트 생성 실패도 원래 대화 행에 실패 placeholder로 표시한다.
  기존에 완료된 이미지는 계속 조회할 수 있다.
- 사용자가 중지한 요청은 중립색 placeholder와 재시도 버튼을 표시한다.

## 13. 모델 관리

앱 실행 시 필요한 모델 파일 존재 여부를 검사한다.

지원:

- 기존 로컬 모델 경로 지정
- 앱 내부에서 모델 다운로드

사용자는 내부 모델 형식이나 추론 백엔드를 이해할 필요가 없어야 한다.

메뉴 이름은 `모델 설정`이며 모델별로 선택된 파일 이름과 준비 상태를 표시한다.
상단 우측에 작업 기록 선택과 모델 설정 버튼을 같은 그룹으로 항상 배치하여
작업 추가 시 버튼이 이동하지 않도록 한다. 선택 메뉴와 옵션의 글자·배경 색은 어두운 테마에서도 읽을 수 있어야 한다.

## 14. 비기능 요구사항

- Windows 11 우선 지원
- 화면 로고, 창과 Windows 실행파일 아이콘은 `docs/ICON.png`를 기준으로 한다.
- 오프라인 사용 가능
- 외부 API 키 불필요
- 사용자 이미지/프롬프트 외부 전송 금지
- 이미지 생성 중 UI 정지 금지
- 앱 종료 시 내부 추론 프로세스 정상 종료
- 생성 이력 손상 방지
- 같은 저장 폴더의 중복 실행으로 진행 중인 요청·이력이 손상되지 않아야 한다.
- Windows portable ZIP 형태로 배포한다.
- 별도 설치 프로그램을 요구하지 않는다.
- 사용자는 ZIP을 압축 해제한 뒤 단일 실행 파일을 더블클릭하여 앱을 실행할 수 있어야 한다.
- Python, Node.js, ComfyUI 등 내부 런타임을 사용자가 별도로 설치하거나 실행하지 않아야 한다.
- 콘솔 창, 로컬 서버 주소, 내부 백엔드 UI 등을 사용자에게 노출하지 않는다.

## 16. 완료 기준

다음이 모두 동작하면 MVP 완료로 본다.

1. 새 작업에서 자연어 요청을 보내면 새 이미지가 생성된다.
2. 두 번째 요청부터 직전 이미지 프롬프트를 기준으로 자연어 수정이 적용된다.
3. 사용자 요청과 생성 이미지가 하나의 대화 흐름으로 표시된다.
4. 이미지를 클릭하면 전체 화면으로 볼 수 있다.
5. 이미지별 실제 프롬프트를 팝업에서 확인할 수 있다.
6. 실제 프롬프트 직접 수정과 다시 생성 결과를 같은 행의 새 이미지 버전으로 만들 수 있다.
7. 이미지의 분기 버튼으로 선택한 이미지까지 복사한 새 세션을 열 수 있다.
8. 원래 세션과 이미지 버전 기록은 보존된다.
9. 같은 행에서 이미지 버전을 좌우로 탐색하고 선택한 프롬프트로 다음 수정을 할 수 있다.
10. 모델, 해상도, Steps, CFG, Seed를 설정할 수 있다.
11. 모든 이미지·프롬프트·설정·분기 관계가 로컬에 저장된다.
12. 앱 재시작 후 기존 작업과 각 행의 선택된 이미지 버전을 복구할 수 있다.
13. Windows에서 별도 런타임 설치 없이 portable ZIP을 풀고 실행 파일만으로 실행할 수 있다.

## 17. 표시 언어

- 한국어와 영어 UI를 지원한다. 메인 화면 왼쪽 상단 로고 옆의 간단한 선택 메뉴에서 변경한다.
- 처음 실행할 때는 기존 동작과 같이 한국어를 사용하며 선택한 언어를 로컬에 저장하고 재시작 시 복원한다.
- 지원하지 않는 저장 언어나 누락된 번역은 영어로 표시한다. 저장 언어를 읽기 전이나 설정을 읽을 수 없는 예외 상황도 영어를 사용한다.
- 모델 상태 등 다른 초기화 작업에 실패해도 독립적으로 읽은 저장 언어로 오류를 표시한다. 정상적으로 읽은 한국어 선택은 유지한다.
- 언어 변경은 대화, 입력 중인 요청, 생성 상태와 설정값을 유지한다. 사용자 요청, 생성 프롬프트, 파일 이름과 모델 고유 이름은 번역하지 않는다.
- 버튼, 접근성 이름, 설정/모델/프롬프트/뷰어 팝업, 진행 상태와 오류를 선택한 언어로 표시한다.
- 번역 리소스는 앱에 포함하며 오프라인에서도 언어를 바꿀 수 있다.
- README.md는 영어, README.ko.md는 한국어이며 각 제목 바로 아래에 언어 간 이동 링크를 둔다.
