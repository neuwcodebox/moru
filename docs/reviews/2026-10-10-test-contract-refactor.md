# 테스트 계약 중심 리팩토링

- 공통 가짜 엔진·스트림·카탈로그·워커를 `tests/support/`로 옮겨 테스트 파일 사이의 import를 제거했다. 구성과 자원 정리는 `make_app`, `app`, `persistent_app` fixture로 관리한다. 일반 애플리케이션 검증은 실제 SQLite 메모리 DB를 사용하며, 재시작·스키마·디스크 실패는 파일 DB로 계속 검증한다. 구성 원칙은 [TECH.md](../TECH.md#28-테스트)에 기록했다.
- 비공개 런타임 캐시·워커 메서드·인증 상태 대신 외부 import·프로세스·OAuth 요청 경계를 사용한다. ID 충돌은 특정 발급 순서 없이 재현하고, 생성 중 거부는 작업별 오류 코드로 검증한다. 스트림은 중복 콜백 횟수에 의존하지 않고 최종 결과·사고/제어 태그 분리·토큰 예산을 검증하며 한 글자씩 나뉘는 입력도 포함한다.
- 프론트엔드 탐색은 CSS 선택 클래스 대신 bridge 입력·뷰어 이미지·초점 복귀로 확인한다. 복사 상태는 접근성 피드백으로 검증하고 실패 후 실제 재시도까지 확인한다. 생성 종료는 가상 시간으로 제어하며 테스트 종료 시 spy와 bridge를 정리한다. 분기 성공과 실패를 독립된 테스트로 분리했다. PNG 비율·뷰어 좌표·행 배치 및 모델 지침·샘플링·캐시 계약에 해당하는 기존 검증은 유지했다.
- 위조 JWT 테스트는 다른 클레임이 모두 유효하고 서명만 틀리도록 수정했다. 별도 프로세스에서 서명 검증만 우회했을 때 해당 테스트가 실패함을 확인했다. 재로그인 host 유지도 다음 OAuth 요청으로 검증한다. 제품 코드·요구사항·의존성은 변경하지 않았다.
- 검증: 전체 `uv run --offline pytest` 611개, 역순 실행 611개, `npm test -- --configLoader runner` 180개, 분기 테스트 분리 전 무작위 순서(seed 1010) 179개, 전체 Ruff 검사 통과. Python은 이 환경의 단일 측정에서 기존 606개 116.97초 → 변경 후 611개 13.75초(최종 병렬 검증 15.74초)였다. Vite 임시 설정 파일의 쓰기 권한 때문에 runner를 사용했다. `npm run check`는 기존 `tsconfig.tsbuildinfo` 쓰기 권한 오류가 있어 동일 설정의 `tsc --project tsconfig.json --noEmit --incremental false`로 타입 검사를 완료했다. 실제 모델/GPU 및 WebView 시각 검증은 기존 별도 검증 범위로 유지한다.
