# 모델 준비 구조와 FLUX.2 klein 4B 지원 — 2026-10-06

모델 준비를 프롬프트 작성과 이미지 생성 영역으로 나누고 이미지 파일은 계열 → 버전 순서로 탐색한다. 실제 모델 선택은 생성 설정에서만 저장하며 파일 준비는 생성값을 변경하지 않는다. 중복 프롬프트 제목과 불필요한 안내를 제거했다. 현재 동작은 [SPEC](../SPEC.md) §4·§9·§13, 모델 정의와 로딩 경계는 [TECH](../TECH.md) §12·§13에 둔다.

SDXL은 선택·파일 준비·다운로드·추론에서 지원하지 않으며 기존 기록 복원에만 이전 이름·기본값을 허용한다. 기존 이미지 열람·Fork·현재 모델로 재생성과, 지원 종료된 모델의 설정 저장·재시도 거부를 검증한다.

FLUX.2 klein 4B 증류 모델을 Anima와 별도 계열로 연결했다. FP8 diffusion, Qwen3 4B FP4 encoder, FLUX.2 VAE를 고정 revision·크기·SHA-256으로 등록했고 원본 Apache 2.0 라이선스와 출처는 [모델 출처](../../vendor/licenses/SOURCES.md)에 둔다. 기존 ComfyUI core·worker·다운로드·OOM 재시도 경로를 재사용하며 새 의존성은 추가하지 않았다. 전용 encoder 타입, 128채널/16배 latent, 영점화 negative, Euler 및 해상도별 sigma를 적용한다. sigma는 고정된 ComfyUI Flux2Scheduler와 수치적으로 일치함을 확인했다. 프롬프트 작성은 공통 해석·보강 규칙과 FLUX 자연어 지침을 사용하며 Anima 태그 참고표는 전달하지 않는다. 모델 전환 후 수정·재생성·재시도는 원래 불변 기록을 유지한다.

FP4 encoder를 기본 다운로드·탐색 경로로 사용하며 기존 FP16 파일과 명시적 경로 선택은 보존한다. 프롬프트 로딩 전 worker의 GPU 가중치와 allocator cache를 필요한 만큼 반환하고, 이미지 생성 전 측정한 가용·반환 가능 VRAM을 파일 크기·해상도 예산과 비교해 프롬프트 LLM을 먼저 해제한다. 충분하면 상주시키며 실제 OOM의 동일 seed 재시도도 유지한다. 완료 후 사용하지 않는 CUDA cache를 반환한다. 메모리 계약과 보수적 추정의 한계는 [TECH](../TECH.md) §9·§11·§13에 둔다.

- Python 전체 343개 및 Ruff 통과. UI 전체 119개, TypeScript와 Vite 빌드도 통과했으며 메모리 변경과 마무리 리팩토링에서 UI 소스는 수정하지 않았다. 파일 우선순위·수동 경로 보존, 가용 VRAM에 따른 유지·해제, 컨텍스트 변경, allocator cache 반환, IPC·취소/OOM과 압축 실패 시 기존 배포본 보존을 GPU·네트워크 없이 검증했다.
- 공식 파일 다운로드·SHA-256 검증 완료. RTX 3060 12GB에서 FP4 encoder는 GPU에 3669.83MiB 적재되어 이전 FP16의 7672.25MiB보다 줄었다. 실제 LLM create·refine 및 1024×1024 생성에 성공하고 시각적으로 확인했다. 사용자 DB와 분리한 Application에서 생성→자연어 수정 두 요청도 성공했다(컨텍스트 4096, 출력 2048, thinking 켜짐·low). 1초 간격 관측 최대치는 이미지 worker RAM 4.47GiB, Python 합계 RAM 7.31GiB, 다른 앱을 포함한 GPU 전체 VRAM 10534MiB였다. 생성 전에 LLM을 해제하고 다음 요청에서 재적재하는 로그를 확인했다. 검증용 이미지·임시 DB는 정리했다.
- 파일·작업 공간 예산은 보수적 추정이며 정확한 메모리 상한이나 품질·속도 비교 실험은 아니다. FLUX 참고 이미지 기반 편집·Base/9B 및 외부 배포 업로드는 포함하지 않았다.

참고: [공식 모델 카드](https://huggingface.co/black-forest-labs/FLUX.2-klein-4B), [ComfyUI 공식 가이드](https://docs.comfy.org/tutorials/flux/flux-2-klein).

마무리 리팩토링은 생성 함수에서 PNG 저장과 FLUX 조건 영점화를 분리하고, 프롬프트 모델의 메모리 계산·로딩이 같은 재사용 판단을 사용하도록 중복 조건을 모았다. 모델 선택·샘플링·메모리 정책·오류 계약은 유지하며 새 클래스·의존성·검사는 추가하지 않았다. 두 모델의 인코딩·파일 교체 실패 시 기존 출력 보존과 임시 파일 정리를 검증하는 테스트 4개를 추가했다.

Windows용 7-Zip을 사용하도록 빌드와 현재 배포 안내를 7z로 전환했다. `release/Moru.7z`(2,115,693,434 bytes)를 새로 빌드했으며 전체 무결성 검사, 6,379개 항목의 경로·크기 일치와 실행 파일·UI·manifest·라이선스의 CRC 비교를 통과했다. `data`·`models`는 비어 있고 모델 가중치는 제외된다. 개발 런타임을 PATH에서 제외한 새 실행 파일의 WebView2 UI·설정 저장·클립보드와 worker의 CUDA 초기화·FLUX 메모리 RPC를 확인했다. 이 배포본에서는 모델 가중치를 다시 적재해 이미지 추론하는 검사는 수행하지 않았다. 빌드 도구와 압축 옵션은 [TECH](../TECH.md#개발-및-검증)에 둔다.

모델 영향 검토에서 프롬프트 형식·기본값·latent/VAE·sigma·파일 준비·전환·재시도·불변 기록의 분리는 확인했다. 확인한 범위에서 FLUX 추가 후 남은 Anima 전제로 인한 누락은 발견하지 않았다. 인코더 계열 검사와 메모리 추정의 정밀도는 공통 한계이며 신규 모델 지원 누락으로 분류하지 않는다. 현재 동작과 한계는 [TECH](../TECH.md) §9·§12에 둔다.

- `512 + 128`은 공통 LLM 출력 예약이며 이미지 인코더 입력 검사가 아니다. GPU·가중치 없이 실제 로컬 토크나이저 경로를 실행해 긴 예문의 Anima Qwen/T5 길이가 901/1101, FLUX 길이가 템플릿 포함 913임을 확인했다. 공식 FLUX도 512 기준이므로 공통 예약을 바꿀 근거는 없고 현재 core는 긴 입력을 받는다. 별도 길이 검사·입력 거부는 추가하지 않으며 작성 지침과 메모리 추정의 적절성을 검토한다. 긴 입력의 GPU 추론 품질은 이 검사로 검증하지 않았다.
