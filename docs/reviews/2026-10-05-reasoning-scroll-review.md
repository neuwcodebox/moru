# 추론 예산과 대화 스크롤 검토

## 변경

추론 예산은 고정 128/256/512토큰 대신 출력 한도에 비례하도록 변경했다.
최종 프롬프트용 512토큰과 여유 128토큰을 먼저 확보하고, 남은 예산의
50%/75%/100%를 낮음/보통/높음에 배정한다. 출력 4096이면 각각
1728/2592/3456토큰이다. 종료 태그와 최종 답변 구분자도 이 예산에 포함한다.
출력 한도가 640 이하이면 자유 추론 없이 답변 구분자와 프롬프트 작성을 시작한다.
자연스럽게 추론을 먼저 끝낸 응답은 예산을 채우도록 강제하지 않는다.
기존 컨텍스트·출력·thinking·추론 수준 설정값은 그대로 복원한다.

이 예약값은 LLM 출력 토큰 기준의 정책이다. 현재 사용 중인 ComfyUI의
`comfy/text_encoders/anima.py`는 Qwen/T5 입력을 512에서 자르지 않는다.
`comfy/ldm/anima/model.py`의 adapter도 짧은 입력만 512로 padding한다.
[Diffusers의 Anima encoder 기본값](https://github.com/huggingface/diffusers/blob/main/src/diffusers/modular_pipelines/anima/encoders.py)은
512이지만 이를 모델의 고정 최대 입력 길이로 해석하지 않는다.
두 엔진의 tokenizer가 달라 여유 공간도 동일 토큰 수를 보장하는 변환식이 아니다.

LLM 지침에서 짧게 생각하라는 제한을 제거했다. 사고 내용은 Application에서
버리고 Job이나 UI bridge에 담지 않는다. UI에는 `생각 중…` 상태만 표시하고,
최종 프롬프트 스트림이 시작하면 `프롬프트 작성 중…`으로 전환한다.
이미지와 텍스트의 복사 버튼은 모두 `복사`로 표시한다.

이중 스크롤은 실제 WebView에서 재현했다. 대화 flex 영역의 최소 높이를 0으로
설정하고 body overflow를 숨겼다. 추가로 복사 버튼의 절대 위치 접근성 문구가
대화 영역의 clipping을 벗어나 페이지 높이를 늘리는 원인을 발견해, 복사 버튼을
해당 문구의 containing block으로 지정했다. 긴 대화와 분기 후에도 페이지는
창 높이에 맞고 대화 영역은 정상적으로 스크롤된다.

## 검증

- 변경 전 테스트에서 고정 추론 예산, 사고 내용 노출, 이미지 복사 명칭 오류를 확인했다.
- 수정 전 빌드에 실제 WebView 회귀 검사를 적용해 바깥 페이지 overflow 실패를 확인했다.
- Python 정상 단위 테스트 177개 통과. 모델·GPU·네트워크를 사용하지 않았다.
- 프론트엔드 테스트 42개, TypeScript 검사와 production build 통과.
- Ruff 검사와 diff whitespace 검사 통과.
- 실제 WebView smoke에서 페이지 overflow 없음, 긴 대화 스크롤, 입력 영역 위치,
  이미지·프롬프트 복사, 분기, hover, 대화·뷰어 키보드 탐색을 확인했다.
  `build/ui-review-411e569d/report.json`에 결과를 기록했다.

이번 검증은 앱의 토큰 배정과 UI 동작을 대상으로 한다. 실제 모델 응답 품질이나
길게 생각했을 때의 속도를 GPU 추론으로 재측정하지 않았다.
