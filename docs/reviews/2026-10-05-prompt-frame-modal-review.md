# 프롬프트 영역과 팝업 입력 격리 검토

## 변경

생성 중과 이미지 hover의 프롬프트를 공통 PromptText로 표시한다. 짧은 내용은
세로 중앙에 배치하고 긴 내용은 이미지 영역 안에서 세로 스크롤한다.
스트리밍은 사용자가 맨 아래를 따르던 경우에만 자동 스크롤한다.

Job에 요청 당시의 width/height를 담고, 완료 이미지 목록에도 저장된 width/height를
전달한다. imageFrameStyle은 생성 중·로딩 중·완료 이미지의 크기를 같은 규칙으로
계산한다. 요청 비율을 유지하고 너비 550px·높이 520px 및 컨테이너 너비에 맞춰
축소한다. 프롬프트나 상태 텍스트는 고정된 frame 안에 배치해 크기를 늘리지 않는다.
진행 중 설정을 바꾸더라도 접수된 요청의 크기는 유지한다.

뷰어를 열 때 hover 표시를 초기화한다. 닫을 때의 프로그램 초점 복원과 마우스 진입
이벤트는 프롬프트를 다시 띄우지 않는다. 실제 마우스 이동과 새 Tab 탐색에서는
정상적으로 표시한다. 키보드 초점과 이미지 선택은 유지한다.

App에서 모든 팝업의 배경 잠금을 공통으로 결정한다. 헤더·대화·입력 영역에 inert를
적용하고, 대화의 overflow·자동 스크롤·선택 행 이동을 잠근다. 설정·모델 설정·
프롬프트 수정 내부 스크롤은 유지하되 스크롤 경계에서 배경으로 이어지지 않게 한다.
뷰어는 passive가 아닌 wheel listener에서 기본 스크롤과 전파를 막고 확대·축소한다.
드래그의 native touch 동작도 막는다.

팝업을 닫을 때 이전 초점으로 돌아가는 브라우저 기본 동작이 배경 스크롤을 움직이는
원인도 실제 WebView에서 재현했다. 공통 Modal이 preventScroll로 초점을 복원하고,
선택 행으로의 이동은 실제 선택이 변경된 경우에만 수행하도록 수정했다.

## 검증

- 변경 전 회귀 테스트로 요청 크기 누락, 팝업 배경 잠금 누락, 휠 이벤트의 기본
  스크롤 미취소를 확인했다. 실제 화면에서는 설정 닫기 후 읽던 위치가 바뀌는 실패도 확인했다.
- Python 단위 테스트 178개 통과. 접수·설정 변경·완료 후 요청 크기 유지도 포함한다.
- 프론트엔드 테스트 49개, TypeScript 검사와 production build 통과.
- Ruff와 diff whitespace 검사 통과.
- 실제 WebView의 일반 창(1080×900)과 작은 창(640×600)에서 짧은 프롬프트 중앙
  정렬, 긴 프롬프트 내부 스크롤, frame 크기 유지, 요청 비율 placeholder를 확인했다.
- 브라우저의 실제 wheel 입력으로 뷰어 확대·축소와 설정·모델 설정·프롬프트 수정의
  스크롤 경계에서 배경 대화가 움직이지 않는 것을 확인했다. 팝업 닫기 후 읽던 위치와
  hover 초기화, 기존 이미지 복사·분기·키보드 탐색도 확인했다.
  팝업 바깥의 어두운 영역에 휠을 올린 경우도 포함한다.
- 실제 화면을 캡처해 프롬프트와 설정 레이아웃을 확인했다. 검증 결과는
  `build/ui-review-bcb5a428/report.json`과 `build/ui-review-e7639498/report.json`에 있다.

추가 native 검사에서 PNG 클립보드 바이트 해시가 한 번 달라지는 실패가 있었다.
화면·입력 검사는 통과했으며, 복사 코드 변경 없이 재실행해 원본 PNG 바이트 일치까지
통과했다. 해시 불일치의 원인을 특정 외부 프로그램으로 확인한 것은 아니다.

모델·GPU·네트워크 없이 UI fixture와 통제된 생성 상태를 사용했다.
이번 변경으로 이미지 추론 결과의 품질을 재측정하지는 않았다.
