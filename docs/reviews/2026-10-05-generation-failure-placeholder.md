# 생성 실패 placeholder UI 검토

## 요구사항과 변경

프롬프트 작성이나 이미지 생성이 실패하면 오류와 재시도 버튼을 이미지 placeholder 안에
중앙 정렬해 표시한다. 붉은 배경과 테두리, 경고 아이콘으로 실패를 구분한다.
기존에 완료된 이미지가 있는 재생성·수동 프롬프트 생성 실패는 원래 대화 행에
실패 placeholder를 추가하며 완료된 이미지의 조회와 버전 기록을 유지한다.
사용자가 중지한 요청에는 중립색과 중지 아이콘을 사용한다.

RequestFailure는 진행 placeholder와 같은 imageFrameStyle을 사용한다.
API 미완료 요청에 저장된 width/height를 추가해 실패 후 설정을 바꾸거나 앱을 다시 열어도
원래 요청 비율을 유지한다. 내용은 프레임 안에 절대 배치하며 공간이 부족하면 내부에서
스크롤한다. 재시도 접수 후에는 목록에 이전 오류가 남아도 Job의 request_id로 숨긴다.

작업 종료 오류를 하단 배너에 중복 추가하던 처리를 제거했다.
bridge 호출·설정·클립보드 등 요청 외 오류의 기존 표시 방식은 유지했다.
추론·저장·재시도 의미나 의존성은 변경하지 않았다. SPEC.md와 TECH.md에 표시 규칙을 반영했다.

## 검증

- 변경 전 프런트엔드 회귀 테스트 5개에서 실패 placeholder 부재를 확인했다.
- 변경 전 Python 회귀 테스트 2개에서 미완료 요청의 이미지 크기 누락을 확인했다.
- 프런트엔드 전체 테스트 91개 통과. 프롬프트·이미지 실패, 하단 배너 중복 방지,
  재생성·수동 생성의 기존 이미지 보존, 재시도 접수 시 이전 오류 숨김,
  사용자 중지 표시와 작업 중 재시도 비활성화를 검증한다.
- Python 일반 전체 테스트 217개와 Ruff 검사 통과.
- TypeScript 검사와 production build 통과.
- 실제 WebView2에서 1080×900 및 640×600 창으로 합성 실패 요청을 표시했다.
  세로 832:1216, 가로 1216:832 비율과 붉은 배경·테두리를 확인했다.
  아이콘·문구·버튼 묶음의 가로·세로 중앙 오차는 1 CSS px 미만이며
  내용 넘침이나 하단 오류 배너 중복이 없다. 캡처 이미지도 직접 확인했다.
- diff 공백 검사 통과.

Python 검증은 설치된 환경을 사용해 `uv run --cache-dir build/uv-cache --no-sync ...`로 실행했다.
기본 uv 캐시에 쓰기 권한이 없어 작업 폴더 안의 캐시를 사용했다.
WebView2는 제한된 실행 환경에서 초기화가 실패해 별도 승인된 실행 환경으로 검증했다.
검증 창은 화면 밖에 두고 합성 데이터만 사용했으며 모델 추론은 실행하지 않았다.
화면 캡처와 측정값은 `build/failure-ui-1080x900/`, `build/failure-ui-640x600/`에 있다.
빌드·검증 생성 파일은 커밋 대상에 포함하지 않는다.
