# 이미지 복사·피드백·탐색·아이콘 검증

검증일: 2026-10-04
기능 커밋: `4f5d2bb`

## 반영한 동작

- 이미지 아래의 `이미지 복사` 버튼은 생성 PNG를 클립보드로 전달한다. PNG 원본과 Windows Bitmap 형식을 함께 제공한다.
- 이미지와 프롬프트 복사 버튼은 성공 시 체크 아이콘으로 잠시 바뀐다. 성공 문구를 화면에 추가하여 팝업 높이를 바꾸지 않는다. 실패 시 재시도할 수 있고 오류를 표시한다.
- 분기 성공 후 새 작업으로 전환한 사실을 잠시 알린다. 실패한 분기에 성공 알림을 표시하지 않는다.
- 이미지 hover 또는 키보드 초점 시 반투명 blur 위에 해당 버전의 실제 생성 프롬프트를 보여 준다. 이미지별 정보를 필요한 시점에 읽고 조회 실패를 커버에 표시한다.
- 상하 방향키는 현재 대화의 이미지 행, 좌우 방향키는 해당 행의 재생성 버전을 탐색한다. 확대 화면에서도 동일한 선택을 사용하며 이미지 변경 시 확대·이동 위치를 초기화한다.
- 텍스트 편집, 설정 팝업, IME 조합은 탐색으로 가로채지 않는다. 생성 중에는 버전을 변경하지 않는다.
- `docs/ICON.png`를 화면 로고로 인라인하고, 같은 원본에서 만든 다중 크기 ICO를 창과 실행파일에 적용한다.
- 이력 문서를 `docs/reviews/YYYY-MM-DD-description.md`로 옮기고 프로젝트 작업 지침에 관리 규칙을 기록했다.

## 추가로 발견하고 수정한 문제

뷰어에서 다른 이미지로 이동한 후 닫으면 Modal의 기본 초점 복귀가 처음 클릭한 이미지로 돌아가 대화 선택까지 되돌렸다.
새 회귀 테스트가 기존 구현에서 실패하는 것을 확인하고, 뷰어를 닫을 때 마지막으로 탐색한 이미지에 초점을 돌리도록 수정했다.
다른 팝업의 기존 초점 복귀 동작은 그대로 사용한다.

## 설계 검토

- 클립보드 I/O는 Windows STA UI thread에 둔다. API는 이미지 조회·경로 검증·명시적인 오류 변환을 담당하며 콜백으로 외부 클립보드 경계를 주입받는다.
- 이미지 표시와 복사는 같은 이미지 바이트 조회 경로를 사용한다. 복사 과정에서 대화나 이미지 기록을 수정하지 않는다.
- 복사 완료 표시의 실제 중복만 `CopyButton`으로 묶고, hover 조회·표시를 `ImagePreview`로 분리했다.
- 탐색은 대화 행 ID와 기존 버전 선택 API를 사용한다. 별도 대화 모델이나 저장 구조를 추가하지 않았다.
- 새 의존성은 추가하지 않았다. 실제 Windows 검증은 일반 단위 테스트와 분리했다.
- 프롬프트 LLM 시스템 지침에는 특정 이미지 생성 모델 이름을 넣지 않는다. 기존 생성·수정 지침 및 해당 테스트를 확인했다.
- README는 앱 소개와 주요 사용 흐름을 중심으로 정리했다. 작은 UI 조작을 기능마다 덧붙이지 않고 SPEC과 이력 문서에서 설명하도록 작업 지침에도 기록했다.

## 실제 Windows 검증

`uv run --extra inference python scripts/smoke_ui_interactions.py`로 실제 WebView2와 Windows 클립보드를 확인했다.
추론 엔진을 실행할 수 없는 테스트 경계와 격리된 합성 대화 기록을 사용한다. 기존 생성 이미지 fixture는 표시 검증에만 사용하며 검증 후 이전 클립보드를 복원한다.

검증 결과: `build/ui-review-58ee7b22/report.json`

- 복사된 이미지 크기 **768×768**, PNG SHA-256이 원본과 일치.
- 프롬프트 복사 문자열 일치, 복사 전후 팝업 높이 유지.
- hover 프롬프트, 대화/확대 화면 방향키, 확대 초기화 및 뷰어 종료 초점 복귀 확인.
- 두 행까지 분기한 새 작업과 원래 세 행의 보존 확인, 분기 알림 및 로고 확인.
- 창 아이콘 32×32로 로드 확인.
- `hover.png`, `copy.png`, `viewer.png`, `fork.png` 캡처를 열어 시각적으로 확인했다.

## 실행파일 검증

`build/portable-a3bfaba9/dist/Moru/Moru.exe`를 새로 빌드했다.
`build/portable-assets-report.json`의 모든 검증이 통과했다.

- PE의 아이콘 그룹과 개별 아이콘 리소스에서 **16/24/32/48/64/128/256** 크기의 원본 ICO 프레임을 바이트 단위로 확인했다.
- ICO의 256×256 이미지가 `docs/ICON.png`를 축소한 이미지와 일치한다.
- 배포 폴더의 ICO 및 HTML이 현재 빌드와 일치하며, 원본 PNG 로고가 HTML에 포함되어 있다.
- 실행파일 안의 애플리케이션 Python 모듈 **19개**를 현재 소스를 컴파일한 코드와 비교하여 일치함을 확인했다. 개발 전용 `moru.__main__` 대신 `app.py`가 실행 진입점이다.
- 배포 폴더의 `models`와 `data`에 사용자 파일이 없는 것을 확인했다.

`scripts/smoke_portable.py build/portable-a3bfaba9/dist/Moru --ui-only`도 통과했다.
개발용 Python/Node/CUDA 경로를 제거한 환경에서 실제 실행파일을 시작하여 기본 설정, 변경한 LLM 설정의 저장, 네이티브 텍스트 복사를 확인했다.
결과: `build/smoke-ab6659cd/report.json`.

배포 ZIP `release/Moru.zip`도 갱신했다. 파일 **6,366개 항목**의 CRC 검증과 배포 폴더 구성 비교를 통과했다.
ZIP의 실행파일·HTML·ICO가 검증한 빌드와 같고, 모델 가중치나 사용자 데이터는 포함되지 않는다.
크기: **3,330,070,710 bytes**. 결과: `build/release-verification-report.json`.

검증 산출물과 생성 이미지, DB, 모델, 배포 빌드는 Git에 포함하지 않는다.
